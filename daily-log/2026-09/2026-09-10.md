## 트랜잭션
- 데이터베이스의 상태를 바꾸는 하나 이상의 연산을 하나의 논리적인 작업 단위로 묶는 것
    - 여러 연산을 묶되, 전부 반영되거나 전부 취소되어야 하는 all-or-nothing 단위임
- 트랜잭션은 두 가지 종료 상태 중 하나로 끝남
    - commit
        - 모든 연산을 성공적으로 반영하고 트랜잭션을 확정하는 종료 상태
    - abort
        - 오류나 충돌로 트랜잭션이 취소되는 종료 상태
- rollback이란 abort에 이르기 위해 트랜잭션 중 발생한 모든 변경을 취소하고 이전 상태로 되돌리는 연산을 가리킴
    - abort는 도달하는 상태이고, rollback은 그 상태로 가기 위한 수단이라는 점에서 층위가 다름

## ACID
- 트랜잭션이 안전하게 처리되기 위해 보장해야 하는 네 가지 성질
    - Atomicity, Consistency, Isolation, Durability
- 네 성질은 각각 보장하는 대상이 다름

### 원자성(Atomicity)
- 트랜잭션에 속한 연산들이 전부 반영되거나 전부 취소되는 성질
- 중간에 실패하면 이미 수행한 연산까지 rollback으로 되돌려 부분 반영을 막음

### 일관성(Consistency)
- 트랜잭션 실행 전후로 데이터베이스가 정의된 규칙을 항상 만족하는 성질
    - 여기서 규칙이란 기본키 제약, 외래키 제약, 도메인 제약, 사용자 정의 무결성 조건 등을 가리킴
- 트랜잭션은 하나의 유효한 상태에서 또 다른 유효한 상태로만 전이해야 함
- 잔액이 음수가 될 수 없다는 제약이 있다면, 그 제약을 깨뜨리는 트랜잭션은 커밋되어서는 안 됨
- 원자성이 "전부 또는 전무"를 보장한다면, 일관성은 그 결과가 규칙을 위반하지 않음을 보장

### 격리성(Isolation)
- 동시에 실행되는 여러 트랜잭션이 서로의 중간 상태에 간섭받지 않는 성질
- 완벽한 격리는 모든 트랜잭션을 한 줄로 세워 차례로 실행한 것과 같은 결과를 보장함
- 그러나 완벽한 격리는 동시 처리 성능을 크게 떨어뜨리므로, 실무에서는 격리 수준을 단계별로 조절함
- 격리 수준을 낮출수록 성능은 오르지만 뒤에서 다룰 이상 현상이 나타날 수 있음

### 지속성(Durability)
- 커밋된 트랜잭션의 결과가 영구적으로 보존되는 성질
- 커밋 이후에는 시스템 장애나 정전이 발생해도 결과가 유실되지 않아야 함
- 데이터베이스는 이를 위해 커밋 시점에 변경을 로그로 디스크에 기록
    - WAL(Write-Ahead Logging)이란 실제 데이터 페이지를 쓰기 전에 변경 내역을 로그에 먼저 기록하는 기법을 가리킴
    - 장애 발생 시 로그를 재생(replay)해 커밋된 변경을 복구함

## 동시성이 낳는 이상 현상
- 격리 수준을 낮추면 여러 트랜잭션이 같은 데이터를 동시에 접근하면서 세 가지 이상 현상이 발생할 수 있음
- 각 현상은 "무엇을 잘못 읽는가"라는 관점에서 구분됨

### dirty read
- 아직 커밋되지 않은 다른 트랜잭션의 변경을 읽는 현상
- T2가 아직 커밋하지 않은 값을 T1이 읽었는데, 이후 T2가 rollback하면 T1은 존재한 적 없는 값을 읽은 셈

```
T2: UPDATE account SET balance = 5000 WHERE id = 1   (아직 커밋 안 함)
T1: SELECT balance FROM account WHERE id = 1   → 5000 읽음
T2: ROLLBACK                                    → balance는 원래 값으로 복귀
결과: T1이 읽은 5000은 실제로 존재한 적 없는 값
```

### non-repeatable read
- 한 트랜잭션 안에서 같은 행을 두 번 읽었을 때 값이 달라지는 현상
- dirty read와의 경계
    - dirty read는 커밋되지 않은 값을 읽는 것
    - non-repeatable read는 그 사이에 끼어든 트랜잭션이 커밋한 값을 읽는 것이며, 읽은 값 자체는 유효함
- T1이 같은 행을 두 번 읽는 사이에 T2가 그 행을 수정하고 커밋하면, 두 읽기의 결과가 어긋남

```
T1: SELECT balance FROM account WHERE id = 1   → 10000 읽음
T2: UPDATE account SET balance = 8000 WHERE id = 1; COMMIT
T1: SELECT balance FROM account WHERE id = 1   → 8000 읽음
결과: 같은 트랜잭션 안에서 같은 행의 값이 10000 → 8000으로 달라짐
```

### phantom read
- 한 트랜잭션 안에서 같은 조건으로 여러 행을 두 번 조회했을 때 행의 집합이 달라지는 현상
- non-repeatable read와의 경계
    - non-repeatable read는 이미 읽은 개별 행의 값이 바뀌는 현상
    - phantom read는 조건에 맞는 행의 개수, 곧 결과 집합의 구성이 바뀌는 현상
- T1이 같은 범위 조건으로 두 번 조회하는 사이에 T2가 그 조건에 맞는 새 행을 INSERT하고 커밋하면, 두 번째 조회에 새 행이 나타남

```
T1: SELECT COUNT(*) FROM account WHERE balance >= 5000   → 3건
T2: INSERT INTO account(id, balance) VALUES(9, 7000); COMMIT
T1: SELECT COUNT(*) FROM account WHERE balance >= 5000   → 4건
결과: 같은 조건의 조회 결과가 3건 → 4건으로 늘어남
```

## 표준 격리 수준 4단계
- 격리 수준(isolation level)이란 트랜잭션이 서로의 간섭을 어디까지 허용하는지를 규정한 등급을 가리킴
- ANSI/ISO SQL 표준은 격리 수준을 네 단계로 정의함
    - 위 세 가지 이상 현상 중 무엇을 허용하고 무엇을 막는지로 각 단계를 구분함
- 아래로 갈수록 격리가 강해지고, 위로 갈수록 동시성 성능이 높아짐

### READ UNCOMMITTED
- 커밋되지 않은 데이터의 읽기를 허용하는 가장 낮은 격리 수준
- 세 가지 이상 현상을 모두 허용함
    - dirty read, non-repeatable read, phantom read가 전부 발생할 수 있음
- 읽기 시 잠금을 거의 사용하지 않아 동시성은 가장 높지만 데이터 정합성 보장은 가장 약함
- 실무에서는 정확성이 거의 요구되지 않는 통계 근사치 조회 등 제한된 경우에만 고려됨

### READ COMMITTED
- 커밋된 데이터만 읽도록 보장하는 격리 수준
- dirty read를 막음
    - 다른 트랜잭션이 커밋한 값만 읽으므로, rollback될 값을 읽는 문제가 사라짐
- non-repeatable read와 phantom read는 여전히 허용함
    - 매 SELECT 시점의 최신 커밋 상태를 읽으므로, 읽기 사이에 커밋된 변경이 반영됨
- Oracle, PostgreSQL, SQL Server의 기본 격리 수준

### REPEATABLE READ
- 한 트랜잭션 안에서 같은 행을 반복 조회해도 항상 같은 값을 보장하는 격리 수준
- dirty read와 non-repeatable read를 막음
    - 표준은 이 차단을 잠금 기반 의미론으로 정의함
    - 읽은 레코드에 공유 잠금을 걸고 트랜잭션 종료까지 유지해, 다른 트랜잭션의 수정을 막음
- 표준에서는 phantom read를 허용함
    - 개별 행의 값은 고정되지만, 조건에 맞는 새 행의 INSERT까지는 막지 못함
- MySQL InnoDB에서는 이 단계에서 phantom read까지 상당 부분 차단함

### SERIALIZABLE
- 모든 트랜잭션을 마치 순차 실행한 것과 동일한 결과를 보장하는 가장 높은 격리 수준
- 세 가지 이상 현상을 모두 막음
    - dirty read, non-repeatable read, phantom read가 전부 발생하지 않음
- 직렬 실행과 같은 결과를 보장하는 방식은 구현에 따라 갈림
    - 잠금 기반 구현(InnoDB, SQL Server 등)은 읽는 범위에 잠금을 걸어 다른 트랜잭션의 삽입과 수정을 차단
    - SSI(Serializable Snapshot Isolation) 기반 구현(PostgreSQL 등)은 잠금 대신 트랜잭션 간 충돌을 감지해, 직렬화가 깨지면 한쪽을 abort시킴
- 어느 방식이든 경합이나 재시도 비용이 커 동시성이 가장 낮음
- 강한 정합성이 반드시 필요한 경우에만 선택

### 격리 수준별 이상 현상 허용 여부
- 아래 표는 ANSI/ISO SQL 표준의 정의를 기준으로 함

| 격리 수준 | dirty read | non-repeatable read | phantom read |
|---------|------------|---------------------|--------------|
| READ UNCOMMITTED | 허용 | 허용 | 허용 |
| READ COMMITTED | 차단 | 허용 | 허용 |
| REPEATABLE READ | 차단 | 차단 | 허용 |
| SERIALIZABLE | 차단 | 차단 | 차단 |

## MySQL 기본 격리 수준
- MySQL의 InnoDB 스토리지 엔진은 기본 격리 수준으로 REPEATABLE READ를 채택함
    - InnoDB란 MySQL의 기본 트랜잭션 지원 스토리지 엔진을 가리킴
    - 다른 주요 DBMS가 READ COMMITTED를 기본으로 삼는 것과 대비됨

### MVCC(Multi-Version Concurrency Control)
- 데이터를 갱신할 때 기존 버전을 덮어쓰지 않고 여러 버전을 함께 유지해 동시성을 제어하는 기법
- InnoDB가 REPEATABLE READ를 낮은 비용으로 구현하는 핵심 기법은 MVCC임
- 각 트랜잭션은 트랜잭션 내 첫 일관된 읽기 시점 기준의 스냅샷을 읽음
    - 스냅샷은 트랜잭션 시작이 아니라 첫 SELECT가 실행되는 시점에 확정됨
    - `START TRANSACTION WITH CONSISTENT SNAPSHOT`을 명시한 경우에만 시작 시점에 스냅샷이 생성됨
    - 다른 트랜잭션이 값을 변경해도, 자신의 스냅샷에 담긴 버전을 계속 읽으므로 반복 조회 결과가 유지됨
- 읽기가 쓰기를 막지 않고 쓰기가 읽기를 막지 않음

### 갭 락을 통한 phantom read 차단
- 표준의 REPEATABLE READ는 phantom read를 허용하지만, InnoDB는 이를 상당 부분 차단함
- 갭 락(gap lock)이란 인덱스 레코드 사이의 간격에 거는 잠금을 가리킴
- 갭에 잠금을 걸면 그 범위에 새 행을 INSERT하려는 트랜잭션이 대기하게 되어, 조건에 맞는 새 행의 출현을 막음
- 넥스트 키 락(next-key lock)이란 레코드 자체에 대한 잠금과 그 앞의 갭 락을 결합한 잠금을 가리킴
    - InnoDB는 범위 조회 시 넥스트 키 락을 사용해 phantom read를 방지함
- 다만, 일반적인 스냅샷 읽기(non-locking read)에서는 애초에 스냅샷을 읽으므로 phantom이 나타나지 않고, 갭 락은 잠금 읽기(`SELECT ... FOR UPDATE` 등)에서 작동함

### 이 기본값을 택하는 이유
- 복제 방식과의 관계
    - MySQL의 전통적 복제 방식은 바이너리 로그(binary log)를 기반으로 함
    - REPEATABLE READ와 갭 락 조합은 문(statement) 단위 복제에서 원본과 복제본의 실행 결과가 어긋나지 않도록 돕는 역할을 함
- 일관된 읽기 보장
    - 하나의 트랜잭션 안에서 여러 번 조회해도 같은 결과를 보장하므로, 긴 트랜잭션의 읽기 정합성을 확보하기에 유리함
- 트레이드오프
    - 갭 락은 범위에 대한 잠금이므로, 잠금 경합과 교착 상태 가능성이 READ COMMITTED보다 높아질 수 있음
    - 짧은 트랜잭션 위주의 고동시성 환경에서는 READ COMMITTED로 낮춰 잠금 범위를 줄이는 선택도 실무에서 흔함

> InnoDB의 REPEATABLE READ는 표준보다 강함\
> 표준은 phantom read를 허용하지만, InnoDB는 MVCC 스냅샷과 갭 락으로 이를 대부분 막음

## 정리
```
트랜잭션 격리 수준
    │
    ├── 트랜잭션과 ACID
    │     ├── 원자성 (전부 또는 전무)
    │     ├── 일관성 (규칙 유지)
    │     ├── 격리성 (상호 간섭 차단)
    │     └── 지속성 (커밋 결과 영구 보존)
    │
    ├── 동시성 이상 현상
    │     ├── dirty read (미커밋 값 읽기)
    │     ├── non-repeatable read (같은 행 값 변화)
    │     └── phantom read (결과 집합 변화)
    │
    ├── 표준 격리 수준 4단계
    │     ├── READ UNCOMMITTED (세 현상 모두 허용)
    │     ├── READ COMMITTED (dirty read 차단)
    │     ├── REPEATABLE READ (non-repeatable read까지 차단)
    │     └── SERIALIZABLE (세 현상 모두 차단)
    │
    └── MySQL 기본 격리 수준
          ├── REPEATABLE READ 채택
          ├── 스냅샷 읽기 → MVCC가 phantom 차단
          └── 잠금 읽기 → 갭 락·넥스트 키 락이 phantom 차단
```
