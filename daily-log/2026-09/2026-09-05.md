## Collections Framework 등장 배경
- Collections Framework란 다수의 데이터를 담고 다루기 위한 표준 자료구조와 알고리즘을 인터페이스와 구현 클래스로 묶어 제공하는 라이브러리를 가리킴
    - `java.util` 패키지에 위치함
- 프레임워크가 없던 시절의 문제는 데이터를 담는 방식이 제각각이었다는 점
    - 기본 배열은 크기가 고정되어 원소 개수가 실행 중에 늘거나 줄 수 없음
    - 중간 삽입, 삭제, 정렬, 검색 같은 연산을 매번 직접 구현해야 했음
    - 자료구조마다 사용법이 달라 코드 재사용이 어려웠음
- Collections Framework가 해결하는 문제는 아래와 같음
    - 크기가 동적으로 늘고 주는 가변 컨테이너를 제공
    - 삽입, 삭제, 검색, 정렬 같은 공통 연산을 표준 메서드로 제공함
    - 서로 다른 구현체가 같은 인터페이스를 공유하므로 구현체를 바꿔도 사용 코드가 거의 그대로 유지됨

### 제네릭 개념
- 제네릭이란 클래스나 메서드가 다루는 데이터 타입을 사용하는 시점에 지정하도록 하는 문법을 가리킴
    - 꺾쇠 괄호 `<>` 안에 타입을 적어 지정함
- `List<String>`은 문자열만 담는 리스트를 뜻함
    - 컴파일 시점에 타입을 검사하므로, 엉뚱한 타입을 넣으면 컴파일 오류로 잡힘
    - 꺼낼 때 형변환(casting)이 필요 없어 코드가 간결하고 안전해짐
- 제네릭이 없으면 컨테이너에서 꺼낸 값이 `Object` 타입이라 매번 명시적 형변환이 필요했고, 잘못된 타입은 실행 중에야 오류로 드러났음

## 인터페이스 계층 구조
- Collections Framework는 크게 `Collection` 계열과 `Map` 계열의 두 갈래로 나뉨
    - `Collection`이란 원소를 하나씩 담는 컨테이너의 최상위 인터페이스를 가리킴
    - `Map`이란 키와 값을 쌍으로 담는 컨테이너의 최상위 인터페이스를 가리킴
- `Collection` 아래에는 성격이 다른 세 하위 인터페이스가 존재함
    - `List`란 순서가 있고 중복을 허용하는 원소 나열을 가리킴
    - `Set`이란 중복을 허용하지 않는 원소 모음을 가리킴
    - `Queue`란 원소를 특정 순서로 넣고 빼는 대기열을 가리킴

```
        Iterable                       Map  ← Collection 미상속, 별도 최상위
           │                            │
       Collection                     HashMap
           │                          TreeMap
   ┌───────┼───────┐               LinkedHashMap
   │       │       │
 List     Set    Queue
   │       │       │
ArrayList HashSet LinkedList
LinkedList TreeSet PriorityQueue
```

- `Iterable`이란 원소를 순차적으로 하나씩 꺼낼 수 있음을 규정하는 최상위 인터페이스를 가리킴
    - `Collection`이 `Iterable`을 상속하므로, `List`, `Set`, `Queue`는 모두 향상된 for문으로 순회 가능함
    - `Map`은 `Iterable`을 직접 상속하지 않으므로, 순회하려면 키 집합이나 엔트리 집합을 거쳐야 함

## ArrayList
- ArrayList란 내부적으로 배열을 사용해 원소를 순서대로 저장하는 `List` 구현체를 가리킴
    - array는 배열을 뜻하며, 이름 그대로 배열 기반 리스트임
    - 원소가 메모리상 연속된 위치에 저장됨
- 인덱스로 특정 위치의 원소에 즉시 접근 가능함
    - 인덱스 접근은 배열의 시작 주소에서 오프셋을 더해 바로 위치를 계산하므로 O(1)임
- 중간 삽입과 삭제는 뒤따르는 원소를 한 칸씩 밀거나 당겨야 하므로 원소 수에 비례하는 비용이 듦
    - 리스트 끝에 추가하는 연산은 대체로 O(1)이나, 내부 배열이 가득 차면 더 큰 배열로 복사하는 확장 비용이 간헐적으로 발생함

```java
import java.util.ArrayList;
import java.util.List;

public class ArrayListExample{
    public static void main(String[] args){
        // 선언: List 타입으로 선언하고 ArrayList로 생성
        // <Integer>는 이 리스트가 Integer만 담는다는 제네릭 타입 지정
        List<Integer> list = new ArrayList<>();

        // 추가: 끝에 원소를 덧붙임
        list.add(10);           // [10]
        list.add(20);           // [10, 20]
        list.add(30);           // [10, 20, 30]
        list.add(1, 15);        // 인덱스 1에 삽입 → [10, 15, 20, 30]

        // 조회: 인덱스로 특정 위치 원소를 꺼냄
        int first = list.get(0);    // 10
        System.out.println(first);

        // 삭제: 인덱스 위치의 원소를 제거
        list.remove(0);         // 10 제거 → [15, 20, 30]

        // 순회: 향상된 for문으로 모든 원소를 하나씩 방문
        for (int value : list){
            System.out.println(value);
        }
    }
}
```
- 인덱스 기반 임의 접근이 잦고, 중간 삽입, 삭제가 드문 경우에 적합함
    - 대부분의 리스트 사용 상황에서 기본 선택지로 삼기에 무난함

## LinkedList
- 각 원소를 노드로 만들어 앞뒤 노드를 포인터로 연결한 `List` 구현체를 가리킴
    - Java의 LinkedList는 앞뒤 양방향으로 연결된 이중 연결 리스트임
- 각 노드는 자신의 값과 함께 이전 노드와 다음 노드를 가리키는 참조를 보유함
    - 원소가 메모리상 연속되지 않고 흩어져 있음
- 인덱스로 특정 위치에 접근하려면 처음이나 끝에서부터 노드를 하나씩 따라가야 하므로 O(n)임
- 위치를 이미 알고 있을 때 그 지점의 삽입과 삭제는 앞뒤 노드의 참조만 바꾸면 되므로 O(1)임
    - 다만 그 위치를 인덱스로 찾아가는 비용이 별도로 들 수 있음

```java
import java.util.LinkedList;
import java.util.List;

public class LinkedListExample{
    public static void main(String[] args){
        // 선언: List 타입으로 선언하고 LinkedList로 생성
        List<String> list = new LinkedList<>();

        // 추가: 끝에 원소를 덧붙임
        list.add("a");          // [a]
        list.add("b");          // [a, b]
        list.add("c");          // [a, b, c]

        // 조회: 인덱스로 원소를 꺼냄 (내부적으로 노드를 따라 이동)
        String first = list.get(0);     // "a"
        System.out.println(first);

        // 삭제: 인덱스 위치의 원소를 제거
        list.remove(1);         // "b" 제거 → [a, c]

        // 순회: 향상된 for문으로 모든 원소를 방문
        for (String value : list){
            System.out.println(value);
        }
    }
}
```
- 리스트 양 끝에서의 삽입과 삭제가 잦은 경우에 이점이 있음
    - 스택이나 큐처럼 끝에서 넣고 빼는 용도로 활용 가능함
- 임의 인덱스 접근이 잦은 상황에서는 ArrayList보다 불리함

## HashSet
- HashSet이란 해시 테이블을 사용해 중복 없는 원소를 저장하는 `Set` 구현체를 가리킴
    - hash는 원소를 정수 값으로 변환하는 해시 함수를 뜻함
    - 이 해시 값을 이용해 원소를 저장할 위치를 결정함
- Set의 핵심 성질은 중복을 허용하지 않는다는 점임
    - 이미 존재하는 원소를 다시 추가하면 무시됨
    - 원소가 같은지는 `hashCode()`와 `equals()` 메서드로 판별함
- 저장 순서를 보장하지 않음
    - 원소가 해시 값에 따라 내부 버킷에 흩어지므로, 넣은 순서와 순회 순서가 일치하지 않음
- 원소 포함 여부 확인, 추가, 삭제가 평균 O(1)임
    - 해시 값으로 위치를 바로 계산하므로 전체를 훑지 않고 접근함

```java
import java.util.HashSet;
import java.util.Set;

public class HashSetExample{
    public static void main(String[] args){
        // 선언: Set 타입으로 선언하고 HashSet으로 생성
        Set<String> set = new HashSet<>();

        // 추가: 원소를 넣음
        set.add("apple");       // [apple]
        set.add("banana");      // [apple, banana] (순서는 보장되지 않음)
        set.add("apple");       // 중복이므로 무시됨

        // 조회: 특정 원소의 포함 여부를 확인
        boolean has = set.contains("apple");    // true
        System.out.println(has);

        // 삭제: 특정 원소를 제거
        set.remove("banana");   // banana 제거

        // 순회: 향상된 for문으로 모든 원소를 방문 (순서 보장 없음)
        for (String value : set){
            System.out.println(value);
        }
    }
}
```

- 중복을 자동으로 걸러내야 하거나, 특정 값의 존재 여부를 빠르게 확인해야 하는 경우에 적합함
    - 순서가 중요하지 않을 때 사용함

## HashMap
- HashMap이란 해시 테이블을 사용해 키와 값을 쌍으로 저장하는 `Map` 구현체를 가리킴
    - map은 하나의 키를 하나의 값에 대응시킨다는 뜻임
    - 키를 해시 함수로 변환한 값을 이용해 값을 저장할 위치를 결정함
- 각 원소는 키와 값의 쌍인 엔트리로 저장됨
    - 엔트리란 키 하나와 그에 대응하는 값 하나를 묶은 단위를 가리킴
- 키는 중복될 수 없으나 값은 중복 가능함
    - 이미 있는 키로 다시 저장하면 기존 값이 새 값으로 덮어씌워짐
- 키로 값을 조회, 추가, 삭제하는 연산이 평균 O(1)임
    - 키의 해시 값으로 위치를 바로 계산하므로 빠름
- 저장 순서를 보장하지 않음

```java
import java.util.HashMap;
import java.util.Map;

public class HashMapExample{
    public static void main(String[] args){
        // 선언: Map 타입으로 선언하고 HashMap으로 생성
        // <String, Integer>는 키가 String, 값이 Integer임을 지정
        Map<String, Integer> map = new HashMap<>();

        // 추가: 키-값 쌍을 넣음
        map.put("apple", 1000);         // [apple=1000]
        map.put("banana", 2000);        // [apple=1000, banana=2000]
        map.put("apple", 1500);         // 기존 키 → 값이 1500으로 덮어씌워짐

        // 조회: 키로 값을 꺼냄
        int price = map.get("apple");   // 1500
        System.out.println(price);

        // 삭제: 키로 엔트리를 제거
        map.remove("banana");           // banana 엔트리 제거

        // 순회: 키-값 쌍을 엔트리 단위로 방문
        // entrySet()은 모든 엔트리를 담은 Set을 반환
        for (Map.Entry<String, Integer> entry : map.entrySet()){
            String key = entry.getKey();
            int value = entry.getValue();
            System.out.println(key + " = " + value);
        }
    }
}
```
- 키를 기준으로 값을 빠르게 찾아야 하는 경우에 적합함
    - 이름으로 전화번호를 찾거나, 상품명으로 가격을 찾는 대응 관계 저장에 사용함
