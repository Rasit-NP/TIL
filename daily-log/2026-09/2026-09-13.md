## 프로세스(process)
- 실행 중인 프로그램의 인스턴스
    - 프로그램은 디스크에 저장된 명령어와 데이터의 정적 집합
    - 프로세스는 프로그램을 메모리에 적재하고 CPU가 실제로 실행하는 동적 실체임
    - 하나의 프로그램에서 여러 프로세스를 동시에 띄울 수 있음
- 프로세스는 실행에 필요한 자원을 독립적으로 소유함
    - 각 프로세스는 자신만의 가상 주소 공간(virtual address space)을 할당받음
    - 가상 주소 공간이란 프로세스가 자신 전용으로 인식하는 논리적 메모리 영역을 가리킴
    - 다른 프로세스의 주소 공간에는 원칙적으로 접근할 수 없음
- 프로세스 간 격리는 안정성의 근거가 됨
    - 한 프로세스가 잘못된 메모리 접근으로 비정상 종료해도 다른 프로세스는 영향을 받지 않음

## 스레드(thread)
- 프로세스 안에서 실행되는 하나의 흐름
    - 하나의 프로세스는 하나 이상의 스레드를 가짐
- 스레드는 CPU 스케줄링의 기본 단위
    - 운영체제가 CPU에 할당하는 대상은 프로세스가 아니라 스레드임
    - 하나의 프로세스가 여러 스레드를 가지면, 각 스레드가 개별적으로 스케줄링됨
- 프로세스와 스레드의 관계는 자원과 실행의 분리로 정리됨
    - 프로세스는 자원을 소유하는 단위임
    - 스레드는 그 자원 위에서 코드를 실행하는 주체 역할을 함

## 스레드 간 공유 메모리 영역
- 같은 프로세스에 속한 스레드들은 프로세스의 주소 공간을 공유함
    - 프로세스 메모리는 크게 코드(Text), 데이터(Data), 힙(Heap), 스택(Stack) 영역으로 나뉨
    - 이 중 코드, 데이터, 힙 영역은 같은 프로세스의 모든 스레드가 함께 사용함
- 각 영역의 공유 내용은 아래와 같음
    - 코드 영역은 실행할 명령어를 담으며, 모든 스레드가 같은 코드를 실행 대상으로 삼음
    - 데이터 영역은 전역 변수와 정적 변수를 담으며, 스레드들이 같은 전역 상태를 봄
    - 힙 영역은 동적 할당된 객체를 담으며, 한 스레드가 할당한 객체를 다른 스레드가 참조할 수 있음

| 메모리 영역 | 담기는 것 | 스레드 간 공유 여부 |
|----------|---------|-----------------|
| 코드(Text) | 실행 명령어 | 공유함 |
| 데이터(Data) | 전역·정적 변수 | 공유함 |
| 힙(Heap) | 동적 할당 객체 | 공유함 |
| 스택(Stack) | 지역 변수·호출 정보 | 공유하지 않음 |

- 힙 공유는 스레드 간 통신을 값싸게 만드는 근거임
    - 별도의 통신 수단 없이 같은 힙 객체에 대한 참조를 주고받는 것만으로 데이터를 공유함
    - 반면 이 공유가 뒤에서 다룰 동기화 문제의 원인이 되기도 함

## 스레드별 스택 독립 소유
- 스택(stack) 영역은 스레드마다 독립적으로 존재함
    - 스택이란 함수 호출 정보와 지역 변수를 저장하는, 후입선출로 관리되는 메모리 영역을 가리킴
    - 함수가 호출되면 스택 프레임이 쌓이고, 반환되면 제거됨
- 스택을 스레드별로 분리하는 이유는 실행 흐름의 독립성에 있음
    - 각 스레드는 서로 다른 함수를 서로 다른 깊이로 호출하며 진행함
    - 지역 변수는 그 스레드만의 계산 중간값이므로 다른 스레드와 섞이면 안 됨
    - 스택이 공유되면 한 스레드의 함수 반환 주소를 다른 스레드가 덮어써 실행 흐름이 어긋남
- 프로그램 카운터도 스레드마다 독립적임
    - 프로그램 카운터(PC)란 다음에 실행할 명령어의 주소를 담는 레지스터를 가리킴
    - 각 스레드가 코드의 서로 다른 지점을 실행하므로 PC 값도 스레드마다 달라야 함

```
[ 단일 프로세스, 스레드 3개 ]

┌───────────────────────────────────────────┐
│  프로세스 주소 공간                           │
│                                           │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐   │  ← 스택은 스레드마다 독립
│  │ Stack T1 │ │ Stack T2 │ │ Stack T3 │   │
│  └──────────┘ └──────────┘ └──────────┘   │
│                                           │
│  ┌─────────────────────────────────────┐  │  ← 힙은 세 스레드가 공유
│  │                 Heap                │  │
│  └─────────────────────────────────────┘  │
│  ┌────────────────────────────────────┐   │
│  │             Data / Text            │   │
│  └────────────────────────────────────┘   │
└───────────────────────────────────────────┘
```

## PCB
- Process Control Block
- 운영체제가 프로세스 하나를 관리하기 위해 유지하는 자료구조
    - 프로세스가 생성될 때 운영체제가 대응하는 PCB를 함께 만듦
    - 커널은 PCB들을 프로세스 테이블에 모아 관리함
- PCB에 담기는 정보는 프로세스 전체에 걸친 관리 정보임
    - 프로세스 식별자(PID)
    - 프로세스 상태(생성, 준비, 실행, 대기, 종료)
    - CPU 레지스터 값과 프로그램 카운터
        - 단일 스레드 모델 기준
        - 멀티스레드에서는 각 TCB로 분리됨
    - 메모리 관리 정보(주소 공간, 페이지 테이블 정보 등)
    - 열린 파일 목록 등 자원 정보
- PCB는 컨텍스트 스위칭의 핵심 근거가 됨
    - 실행 대상이 CPU에서 내려갈 때 그 실행 상태를 제어 블록에 저장함
        - 단일 스레드 모델에서는 PCB, 멀티스레드에서는 TCB
    - 다시 CPU를 얻을 때 해당 제어 블록에서 상태를 복원해 중단 지점부터 이어감

## TCB
- Thread Control Block
- 운영체제가 스레드 하나를 관리하기 위해 유지하는 자료구조
    - 프로세스가 여러 스레드로 나뉘면 각 스레드가 자신의 TCB를 가짐
- TCB에는 스레드 실행에 고유한 정보만 담김
    - 스레드 식별자(TID)
    - 해당 스레드의 레지스터 상태
    - 프로그램 카운터
    - 스택 포인터
- PCB와 TCB의 역할 분담은 공유와 독립의 경계와 일치함
    - 같은 프로세스의 스레드들은 PCB에 담긴 대부분의 프로세스 관리 정보를 공유함
    - 실행에 직접 관련된 정보(레지스터, PC, 스택 포인터)만 PCB에서 분리해 각 TCB에 둠
    - TCB는 자신이 속한 프로세스의 PCB를 가리키는 참조를 가짐

| 구분 | PCB | TCB |
|-----|-----|-----|
| 관리 대상 | 프로세스 | 스레드 |
| 담는 정보 | 주소 공간·자원·상태 등 프로세스 전역 정보 | 레지스터·PC·스택 포인터 등 실행 고유 정보 |
| 개수 관계 | 프로세스당 1개 | 스레드당 1개 |
| 참조 방향 | 소속 TCB들을 포함 | 소속 PCB를 참조 |

## 컨텍스트 스위칭
- 컨텍스트 스위칭(context switching)이란 CPU가 실행하던 대상을 다른 대상으로 교체하는 처리
    - 컨텍스트(context)란 실행 재개에 필요한 상태 정보 전체를 가리킴
    - 레지스터 값, 프로그램 카운터 등이 컨텍스트에 해당함
- 컨텍스트 스위칭의 기본 절차는 저장과 복원의 반복임
    - 실행 중이던 대상의 컨텍스트를 그 제어 블록(PCB 또는 TCB)에 저장함
    - 스케줄러가 다음에 실행할 대상을 선택함
    - 선택된 대상의 컨텍스트를 제어 블록에서 CPU로 복원함
    - 복원된 프로그램 카운터가 가리키는 지점부터 실행을 이어감

## 프로세스 전환이 더 비싼 이유
- 프로세스 간 컨텍스트 스위칭은 스레드 간 전환보다 비용이 큼
    - 두 경우 모두 레지스터와 프로그램 카운터를 저장하고 복원하는 공통 비용은 동일함
    - 차이는 주소 공간 교체 여부에서 발생
- 주소 공간 교체는 페이지 테이블 전환을 동반함
    - 페이지 테이블(page table)이란 가상 주소를 물리 주소로 변환하는 대응표를 가리킴
    - 프로세스마다 주소 공간이 다르므로, 프로세스를 바꾸면 페이지 테이블도 함께 바꿔야 함
    - x86-64에서는 최상위 페이지 테이블의 물리 주소를 담는 CR3 레지스터를 교체하는 방식으로 이뤄짐
- TLB 무효화가 주된 추가 비용임
    - TLB(Translation Lookaside Buffer)란 최근에 가상 주소 대 물리 주소 변환 결과를 캐싱하는 하드웨어 캐시를 가리킴
    - 별도 기법이 없다면, 주소 공간이 바뀔 때 이전 프로세스의 TLB 항목은 새 프로세스에 유효하지 않으므로 무효화됨
    - 무효화 직후 새 프로세스는 차가운 TLB로 시작하며, 한동안 TLB 미스가 잦아져 페이지 테이블을 순회하는 비싼 변환이 빈번해짐
- 같은 프로세스 내 스레드 전환은 이 비용을 피함
    - 스레드들은 같은 주소 공간을 공유하므로 페이지 테이블을 바꾸지 않음
    - 따라서 CR3 교체도, 그로 인한 TLB 무효화도 발생하지 않음
    - 스레드 전환에서 바뀌는 것은 레지스터, PC, 스택 포인터 정도임
- 다만 TLB 무효화가 항상 강제되는 것은 아님
    - ARM의 ASID(Address Space Identifier)나 x86의 PCID(Process-Context Identifier)는 TLB 항목에 프로세스 식별 태그를 붙이는 기법
    - 이 기법을 쓰는 프로세서에서는 태그로 프로세스를 구분하므로, 프로세스 전환 시 TLB 전체 무효화를 줄이거나 피할 수 있음
    - 이는 특정 하드웨어의 최적화 기능이며, 태그가 없거나 항목이 소진된 상황 등에서는 여전히 무효화가 일어날 수 있음

| 구분 | 프로세스 전환 | 스레드 전환(동일 프로세스) |
|-----|------------|---------------------|
| 레지스터·PC 저장·복원 | 발생함 | 발생함 |
| 주소 공간(페이지 테이블) 교체 | 발생함 | 발생하지 않음 |
| TLB 무효화 | 발생함(ASID/PCID로 완화 가능) | 발생하지 않음 |
| 상대적 비용 | 큼 | 작음 |

## 멀티스레드
- 하나의 프로세스가 여러 스레드를 두어 작업을 나눠 실행하는 방식
    - 같은 작업을 여러 프로세스로 나누는 멀티프로세스 방식과 대비됨

### 멀티스레드의 이점
- 자원 생성 비용이 낮음
    - 새 프로세스를 만들면 독립된 주소 공간과 자원 일체를 새로 할당해야 함
    - 새 스레드는 기존 프로세스의 주소 공간과 자원을 공유하므로, 스택과 TCB 정도만 추가로 마련하면 됨
- 스레드 간 통신 비용이 낮음
    - 프로세스 간 통신은 주소 공간이 분리되어 있어 별도의 IPC(Inter-Process Communication) 수단을 거쳐야 함
    - IPC란 파이프·공유 메모리·소켓 등 프로세스 사이의 통신 수단을 가리킴
    - 스레드는 힙과 데이터 영역을 공유하므로 별도 수단 없이 같은 메모리를 직접 읽고 씀
- 전환 비용이 낮음
    - 앞서 다룬 대로 스레드 전환은 주소 공간 교체와 TLB 무효화를 피하므로 프로세스 전환보다 저렴함

### 멀티스레드의 대가
- 공유 자원은 동기화 문제를 낳음
    - 동기화 문제란 여러 스레드가 공유 자원에 동시에 접근할 때 실행 순서에 따라 결과가 어긋나는 현상을 가리킴
    - 힙과 데이터 영역이 공유되기 때문에, 여러 스레드가 같은 변수를 동시에 읽고 쓰면 값이 오염될 수 있음
    - 이를 막기 위한 수단(잠금 등)은 그 자체로 구현 복잡도와 성능 비용을 더함
- 한 스레드의 비정상 종료가 프로세스 전체에 파급됨
    - 스레드들은 같은 주소 공간을 공유하므로 격리되어 있지 않음
    - 한 스레드가 잘못된 메모리 접근으로 프로세스를 비정상 종료시키면, 같은 프로세스의 모든 스레드가 함께 종료됨
    - 프로세스 간에는 이러한 격리가 보장되지만, 스레드 간에는 보장되지 않음
- 이점과 대가의 원인은 동일함
    - 자원 공유가 생성·통신·전환 비용을 낮추는 이점의 근원임
    - 동시에 그 공유가 동기화 문제와 격리 부재라는 대가의 근원이기도 함

## 정리
```
프로세스와 스레드
    │
    ├── 정의
    │     ├── 프로세스 : 실행 중인 프로그램, 독립된 주소 공간 소유
    │     └── 스레드 : 프로세스 내 실행 흐름, CPU 스케줄링 단위
    │
    ├── 메모리 공유 범위
    │     ├── 공유 : 코드 · 데이터 · 힙
    │     └── 독립 : 스택 · PC · 레지스터
    │
```
