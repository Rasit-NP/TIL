## `std::string_view`의 정의
- `std::string_view`란 문자열 데이터를 소유하지 않고 참조만 하는 경량 뷰 타입을 가리킴
    - view는 원본을 들여다보는 창을 뜻하며, 데이터 사본을 갖지 않고 남의 메모리를 가리키기만 함을 명명에 담음
    - C++17에서 표준 라이브러리에 추가됨
- 내부 구조는 시작 포인터와 길이 두 필드 뿐임
    - 우너본 문자 배열의 시작 주소를 가리키는 포인터 하나
    - 참조 구간의 바이트 수를 담는 길이 정수 하나
- `std::string`과의 경계가 핵심
    - `std::string`은 자신만의 힙 버퍼를 소유하고 수명을 책임짐
    - `std::string_view`는 버퍼를 소유하지 않으면 수명을 책임지지 않음
    - 뷰가 가리키는 원본이 살아 있는 동안에만 뷰가 유효함

### zero-copy 파싱의 정의
- zero-copy란 데이터를 새 버퍼로 복사하지 않고 원본 버퍼를 직접 참조해 처리하는 기법
    - 복사(copy) 비용이 0이라는 의미를 명명에 담음
- 파싱 결과인 method, path, version을 `std::string`으로 복사해 담으면 매 요청마다 힙 할당과 바이트 복사가 발생함
- 이 값들을 원본 `buffer_`의 특정 구간을 가리키는 `std::string_view`로 반환하면 복사가 사라짐
    - 파서가 이미 보유한 버퍼를 그대로 가리키므로 추가 할당이 없음

### zero-copy의 전제 조건
- zero-copy는 원본 버퍼가 뷰보다 오래 살아 있어야 성립함
    - 뷰는 원본을 가리키기만 하므로 원본이 사라지면 뷰는 해제된 메모리를 가리킴
- 원본 버퍼의 주소가 뷰 발급 이후 바뀌지 않아야 함
    - 주소가 바뀌면 뷰의 시작 포인터가 옛 주소를 그대로 가리켜 무효가 됨
- 이 두 전제가 깨지는 지점이 곧 dangling 발생 지점

## dangling의 정의
- dangling이란 이미 무효화된 메모리를 가리키는 포인터나 뷰의 상태를 가리킴
- `std::string_view`가 dangling되는 두 경로가 있음
    - 원본 `std::string`이 소멸해 버퍼가 해제된 경우
    - 원본 `std::string`이 재할당되어 옛 버퍼가 해제된 경우
- dangling 뷰를 읽으면 use-after-free가 발생함
    - use-after-free란 해제된 메모리를 해제 이후에 접근하는 오류를 가리킴
    - 미정의 동작(UB)이므로 크래시, 쓰레기 값 읽기, 조용한 오작동 중 무엇이든 나타날 수 있음

## `std::string` 재할당 시 무효화 규칙
- `std::string`은 내부에 힙 버퍼를 두고 문자 데이터를 저장함
    - 현재 담을 수 있는 용량을 capacity로 관리함
- `append`로 데이터를 이어 붙일 때 결과 크기가 capacity를 초과하면 재할당이 일어남
- 재할당이 일어나면 기존 버퍼를 가리키던 모든 참조가 무효화됨

### 파싱 도중 발급이 즉시 dangling인 이유
- 재개 파싱 모델에서 `buffer_`는 청크가 도착할 때마다 `append`로 계속 커짐
- 파싱 도중에 method나 path 뷰를 발급하면, 다음 청크의 `append`가 재할당을 일으키는 순간 그 뷰가 전멸함
    - 발급 당시의 시작 주소가 옛 버퍼를 가리크는데 옛 버퍼는 이미 해제됨
- 따라서 뷰 발급은 버퍼가 더 이상 자라지 않는 시점 이후여야 안전함

### `Done` 확정 시점 일괄 발급
- 뷰 발급을 `Done` 확정 시점 단 1회로 고정
    - 이 시점 이후로 `buffer_`가 자라지 않으므로 재할당이 일어나지 않음
    - method, path, version 세 뷰를 `buffer_`의 offset 기준으로 한꺼번에 발급함
- 뷰의 수명은 파서 인스턴스의 수명에 종속됨
    - 뷰가 가리키는 `buffer_`가 파서의 멤버이므로, 파서가 살아 있는 동안에만 뷰가 유효함
    - 파서가 소멸하면 `buffer_`가 해제되어 발급된 모든 뷰가 dangling됨

## 발급 위치의 offset 표현
- 파싱 위치를 포인터가 아닌 정수 offset으로 다루면 재할당 중에도 논리적 위치가 보존됨
    - offset은 버퍼 시작으로부터 상대 거리이므로 기반 주소가 바뀌어도 같은 논리적 지점을 가리킴
- `Done` 확정 시점에는 재할당이 끝난 상태이므로, 이때 offset을 실제 포인터로 환산해 뷰를 만듦
- 요청 라인 파싱에서 `substr(0, crlf)`로 부분 문자열을 복사하던 코드를 제거
    - `substr`은 새 `std::string`을 만들어 복사하므로 zero-copy 목표에 어긋남
    - 대신 `buffer_`의 해당 구간을 가리키는 뷰를 발급

```cpp
// Done 확정 시점, buffer_가 더 이상 자라지 않음이 보장된 뒤 발급
// method/path/version을 buffer_ 구간을 가리키는 view로 만듦
method_  = std::string_view(buffer_.data() + method_off_, method_len_);
path_    = std::string_view(buffer_.data() + path_off_,   path_len_);
version_ = std::string_view(buffer_.data() + ver_off_,    ver_len_);
```

## 소유권 계약 주석
- 소유권 계약이란 어떤 객체가 어떤 자원의 수명을 책임지는지를 코드에 명시하는 약속을 가리킴
- 반환된 뷰가 파서 내부 `buffer_`에 종속됨을 헤더에 주석으로 남겨야 함
    - 뷰의 유효 기간이 파서 생존 기간과 일치함을 호출자에게 알림
    - 파서 소멸 후 뷰를 읽으면 dangling임을 경고함

```cpp
// 소유권 계약:
// 반환되는 string_view는 이 파서의 내부 buffer_를 가리킴
// 파서 인스턴스가 살아 있는 동안에만 유효
// 파서 소멸 후 뷰를 읽으면 use-after-free가 됨
std::string_view method() const;
```

## AddressSanitizer
- AddressSanitizer(ASan)란 메모리 오류를 런타임에 탐지하는 컴파일러 계측 도구를 가리킴
    - `-fsanitize=address` 플래그로 활성화함
- 해제된 메모리 접근, 버퍼 오버플로, 스택 밖 접근 등을 감지해 즉시 진단을 출력함
- 파서 테스트를 `-fsanitize=address`로 빌드해 실행하면 발급된 뷰의 dangling 여부를 확인할 수 있음
    - 정상 스위트가 통과하고 ASan 경고가 없으면 발급 시점 설계가 올바름을 뒷받침함

### ASan 음성 테스트
- ASan은 정적 분석이 아니라 런타임 계측이므로, dangling 참조가 존재만 해서는 잡지 못함
    - 코드가 그 dangling 뷰를 실제로 읽는 순간에만 오류를 보고함
- 따라서 파서 소멸 이후 발급된 뷰를 읽는 경로를 실제로 실행해야 use-after-free가 드러남
- 이를 위해 음성 테스트를 하나 추가함
    - 음성 테스트란 오류가 발생해야 정상인, 실패를 의도적으로 유발하는 테스트를 가리킴
    - 파서를 소멸시킨 뒤 발급 뷰를 읽어 ASan이 use-after-free를 보고하는지 확인함
- 이 음성 테스트는 정상 스위트와 분리해 별도로 둠
    - 정상 스위트에 섞으면 의도된 오류가 정상 실행을 오염시켜 전체 통과 판정을 방해

## 헤더 map 뷰화 제약
- 헤더 컨테이너의 값도 뷰로 바꾸면 추가 복사를 없앨 수 있으나, 이번 범위에서는 제외
- key를 뷰로 만들 수 없는 근본 이유가 있음
    - 헤더 field-name은 `to_lower`로 소문자 정규화된 문자열을 key로 사용함
    - 정규화된 소문자 key는 원본 `buffer_` 안에 그대로 존재하지 않음
        - 원본 버퍼에는 대소문자가 섞인 원래 표기가 들어 있음
    - 원본에 없는 바이트열은 가리킬 대상이 없으므로 뷰로 표현할 수 없음
- 따라서 정규화 key는 별도 소유 문자열로 남겨 둠

```
string_view zero-copy 리팩터
    │
    ├── string_view
    │     ├── 비소유 참조 (포인터 + 길이)
    │     ├── 원본 수명에 종속
    │     └── string(소유)과의 경계
    │
    ├── dangling
    │     ├── 원본 소멸 → 무효
    │     ├── 재할당 → 옛 버퍼 해제 → 무효
    │     └── use-after-free (UB)
    │
    ├── 발급 계약
    │     ├── 파싱 도중 발급 금지 (append 재할당 위험)
    │     ├── Done 확정 1회 일괄 발급
    │     ├── offset 기준 위치 표현
    │     └── 뷰 수명 = 파서 수명
    │
    ├── 검증
    │     ├── 소유권 계약 주석
    │     ├── ASan (-fsanitize=address)
    │     ├── 실제 접근 밟아야 탐지
    │     └── 음성 테스트 분리
    │
    └── 제약·순서
          ├── 헤더 key 뷰화 불가 (정규화 key 원본 부재)
          ├── 테스트 통과 상태에서만 착수
          └── 미초기화 Result 선정리
```
